# بوت واتساب — إرسال رمز التسجيل

خدمة صغيرة تحمل حساب واتساب واحدًا وترسل عبره رمز التحقّق. الباكند لا يعرف عنها شيئًا إلا
عنوانها وكلمة سرّ مشتركة: يطلب «أرسل هذا الرمز لهذا الرقم»، وتُجيب بنعم أو بسبب الرفض.

## اقرأ هذا أولًا

هذه الخدمة تُشغّل حسابًا شخصيًا عاديًا عبر مكتبة غير رسمية (Baileys)، لا عبر WhatsApp Business
Cloud API. وهذا **خارج شروط واتساب**:

- يمكن حظر الرقم **بلا إنذار وبلا استئناف**. ساعتها يتوقّف التسجيل عن كل المستخدمين حتى يُربَط
  رقم جديد.
- الرقم المستخدَم يجب أن يكون رقمًا مخصّصًا لهذا الغرض — لا رقمك الشخصي ولا رقم العمل.
- لا شيء آخر في المشروع يعتمد على هذه الخدمة. المرسِل في الباكند ينفّذ نفس العقد
  (`OtpSender`) الذي ينفّذه مرسِل الـ Cloud API الرسمي، فالانتقال إلى الطريق الرسمي
  **إعداد واحد** لا إعادة كتابة:

  ```
  OTP_PROVIDER=whatsapp_bot   →   OTP_PROVIDER=whatsapp
  ```

القواعد المكتوبة في `src/queue.js` موجودة لتقليل احتمال الحظر: فاصل ٤ ثوانٍ بين الرسائل مع
تشويش عشوائي حتى لا يكون الإيقاع آليًا، سقف ٦٠ رسالة في الساعة المتحرّكة، ومهلة دقيقة لكل رقم
على حدة. عند تجاوز السقف **ترفض الخدمة ولا تُراكم**: طابور يُفرَّغ لاحقًا هو دفعة مفاجئة
لاحقًا، وهي بالضبط ما يُحظَر عليه الحساب.

## الربط (مرّة واحدة)

```
cd services/whatsapp-bot
npm install
WHATSAPP_AUTH_DIR=./auth npm run pair
```

ثم من واتساب على الهاتف: **الإعدادات ← الأجهزة المرتبطة ← ربط جهاز**، وامسح الرمز الظاهر.

ما يُكتَب في `./auth` هو الحساب نفسه. احفظه، ولا تضعه في git (مستثنى في `.gitignore`)، ولا
تبنِه داخل صورة Docker. إن فُقد، لا يستطيع أحد التسجيل حتى يحضر شخص بالهاتف ليمسح رمزًا جديدًا.

الربط يحتاج طرفيّة تفاعليّة، لذا الأسهل أن يجري **محليًا** ثم تُنسَخ `auth/` إلى القرص الدائم
على الخادم — أو أن يُشغَّل `npm run pair` داخل جلسة shell على الخادم نفسه والقرص مربوط.

## التشغيل

```
WHATSAPP_BOT_TOKEN=<سرّ طويل> WHATSAPP_AUTH_DIR=./auth npm start
```

أو بـ Docker، والقرص هو ما يجب أن يبقى بين الإعادات:

```yaml
services:
  whatsapp-bot:
    build: ./services/whatsapp-bot
    environment:
      WHATSAPP_BOT_TOKEN: ${WHATSAPP_BOT_TOKEN}
    volumes:
      - whatsapp-auth:/app/auth
    # لا ports: الخدمة لا تُنشَر على الإنترنت.
volumes:
  whatsapp-auth:
```

**لا تنشرها على الإنترنت.** خدمة ترسل رسائل واتساب لأي رقم يُطلَب منها هي مدفع إزعاج إذا
وصلها غير الباكند. تسمع على شبكة خاصّة فقط، والسرّ المشترك هو ما يمنع بقيّة ما على تلك الشبكة
من استخدامها.

### الإعدادات

| المتغيّر | المعنى |
|---|---|
| `WHATSAPP_BOT_TOKEN` | السرّ المشترك مع الباكند. لا تبدأ الخدمة بدونه. |
| `WHATSAPP_AUTH_DIR` | مجلّد بيانات الجلسة (افتراضيًا `./auth`، وفي الصورة `/app/auth`). |
| `PORT` | افتراضيًا `8085`. |
| `LOG_LEVEL` | افتراضيًا `warn`. |

وفي الباكند، نفس القيم من الجهة الأخرى:

```
OTP_PROVIDER=whatsapp_bot
WHATSAPP_BOT_URL=http://whatsapp-bot:8085
WHATSAPP_BOT_TOKEN=<نفس السرّ>
```

## الواجهة

| الطلب | الجواب |
|---|---|
| `GET /health` | `200` مع حالة الجلسة، أو `503` إذا كانت مقطوعة. بلا سرّ. |
| `POST /send` | `{"phone": "+9639…", "code": "482913"}` مع `Authorization: Bearer <السرّ>` |

ما يُجيب به `POST /send`:

| الحالة | `reason` | معناها في الباكند |
|---|---|---|
| `200` | — | أُرسِل |
| `400` | `bad_request` / `invalid_number` | رقم أو رمز غير صالح — لا يُعاد |
| `422` | `not_on_whatsapp` | لا حساب واتساب لهذا الرقم — لا يُعاد |
| `429` | `hourly_cap` / `too_soon_for_this_number` | مع `retryAfterMs` — يُعاد لاحقًا |
| `503` | `disconnected` / `logged_out` | الجلسة ساقطة — يُعاد لاحقًا |
| `502` | `send_failed` | رفضه واتساب نفسه — يُعاد لاحقًا |
| `401` | `unauthorised` | السرّ لا يطابق |

الفرق بين «لا يُعاد» و«يُعاد لاحقًا» هو ما يقرّر إن كان الشخص يُبلَّغ أن رقمه لا يصلح أم
يُطلَب منه الانتظار. و`503` موجودة تحديدًا كي يفشل التسجيل بصوت عالٍ: أهون أن يُقال «تعذّر
إرسال الرمز» من أن ينتظر أحد رمزًا لن يأتي أبدًا.

## ماذا لا يُكتَب في السجلّ

لا الرمز ولا الرقم ولا السرّ. ما يُكتَب هو حالة الجلسة وسبب الرفض ورقم الحالة — أي ما يحتاجه
من يصلح خللًا، لا سجلّ بمن سجّل ومتى.

## الاختبارات

```
npm test
```

عشر حالات على قواعد الإيقاع والعنونة، بساعة يملكها الاختبار: بلا شبكة وبلا جلسة وبلا وقت
حقيقي. ما لا يستطيع اختبار إثباته هو أن الرسالة تصل فعلًا — ذاك عمل تجربة واحدة على رقم
اختبار بعد الربط.

## إذا حُظِر الرقم

1. `GET /health` يقول `loggedOut: true`، والخدمة تتوقّف عن إعادة المحاولة — المحاولة في حلقة
   هي ما يفعله حساب محظور.
2. التسجيل متوقّف الآن. القرار: رقم جديد يُربَط، أو `OTP_PROVIDER=whatsapp` والطريق الرسمي.
3. لا تحذف `auth/` قبل أن تعرف السبب؛ القطع المؤقّت يبدو شبيهًا والجلسة تعود وحدها.
